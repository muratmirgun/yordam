# Yordam v0.3.0 Sequential Subagent Acceptance

## Sequential execution contract

Yordam v0.3.0 supports one local sequential child at a time for a parent turn.
Delegation is depth one and bounded by the frozen runtime manifest: the default
configuration enables at most four attempts per parent turn, sixteen child
tool calls per attempt, and a 600-second deadline. A child uses the exact same
provider/model pair and frozen skill catalog as its parent, but its derived
tool exposure omits `subagent`.

The durable ordering contract is parent request/wait, child manifest and
ordinary turn effects, child terminal receipt, parent receipt attachment, then
parent provider continuation. The managed operation lane is yielded and
reacquired around that child interval, so parent and child effects do not run
concurrently. Cancellation is covered at provider streaming, interactive
approval, and shell-process boundaries. Recovery attaches an exact committed
receipt once; ambiguous dispatched effects become `uncertain` and are not
implicitly retried. An explicit later delegation uses a new attempt, child
session, task, and turn identity.

Receipts project changed files, executed commands/tests, evidence IDs, usage,
and unknown effects only from the committed child journal. Model prose remains
a bounded summary and cannot manufacture effect evidence. The receipt does not
verify the parent task or assert that the parent goal is complete.

The implementation has no concurrent child scheduling, worktree management,
agent transport to another host, free-form child mailbox, or child-specific
provider/model selection.

## Secret and authority boundaries

The canonical built-in orchestration descriptor is intercepted only after its
source revision and descriptor digest match the frozen catalog. Its
authorization request binds the exact session, task, turn, activity, call,
runtime generation, policy generation, and dispatch digest, and carries no
file resource or ordinary executable tool handle. Every child file or shell
effect receives a separate child-bound plan and permission decision.

The parent permission mode is an authority ceiling. Parent mutable session
grants and trusted-shell acknowledgement are excluded, so child shell use can
prompt independently. Provider credentials remain limited to the configured
authorization header. The acceptance fixture seeds one secret through parent
and child prompts, provider errors, shell output, and child summaries, then
checks raw, JSON-escaped, base64, and hexadecimal variants across model request
bodies, receipts, evidence/events, application output, restart snapshots, TUI
cards, and debug logs.

Task 9 acceptance exposed and fixed three production-composition gaps: the
canonical orchestration marker previously lacked a dispatch-free authorization
planning seam; typed transient child stages were incorrectly decoded as legacy
payloads; and structured edit results were not committed as `file.changed`
facts for receipt projection. The file-effect path now accepts only structured
built-in edit output bound to the exact canonical descriptor, authorized
resource and pre/postimage digests. It never derives a changed-file claim from
diff text or assistant content.
