## User-facing behavior

Manual `/compact` requires an idle session and writes a native durable compaction
event bound to summary evidence. Automatic compaction uses the same summary
contract after a known-window reserve threshold is reached; it remains
unavailable when disabled or when the window is unknown. A context-too-large
provider failure exposes `/compact` and does not receive a normal provider retry.

Compaction never rewrites the journal. Context reconstruction verifies the
summary-evidence binding and retains the newer uncompacted suffix. A summary is
derived context, never original evidence. Cancellation gets a durable terminal
result. Known non-commits terminalize safely; an unprovable final commit remains
uncertain until recovery can resolve it.

## Security limits

The acceptance fixtures seed provider-key and sentinel values. The configured
provider key is deliberately observed in the outbound `Authorization: Bearer`
header; the body-only provider capture, stored evidence, events, TUI-visible
output, logs, and public errors must omit both secrets. This redaction boundary
reduces accidental disclosure but is not a sandbox and does not make arbitrary
model or user content safe to disclose.
