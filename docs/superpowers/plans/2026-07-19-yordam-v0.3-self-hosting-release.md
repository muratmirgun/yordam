# Yordam v0.3 Self-Hosting Acceptance and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove that one released Yordam binary can use trusted project skills, one sequential child, existing coding tools, compaction, and restart recovery to make and verify a bounded change in a disposable checkout of its own exact source commit on macOS and Linux.

**Architecture:** Acceptance builds Yordam from a clean exact commit, clones that commit with local no-hardlink Git into a temporary workspace, runs the real TUI under a PTY with isolated HOME/data/log roots, and drives a deterministic OpenAI-compatible server through parent, child, continuation, and compaction responses. Assertions inspect both visible TUI behavior and canonical journals/evidence/workspace state. The release gate runs the combined v0.3 umbrella plus v0.1/v0.2 regressions before packaging/publishing, and evidence is written only after a clean successful run.

**Tech Stack:** Go 1.26.4, acceptance build tag, local Git, PTY fixture, deterministic `httptest` SSE server, existing GoReleaser/Syft release pipeline, GitHub Actions macOS/Linux runners.

## Global Constraints

- This plan begins only after the compaction, skills, and sequential-subagent plans pass their completion gates.
- The harness never runs Yordam against or writes into the developer’s primary checkout.
- Use `git clone --local --no-hardlinks` into `t.TempDir()` and checkout the exact tested commit.
- Build the tested binary from that exact clean commit, not from a different worktree.
- No network credential or external provider is required; provider behavior is deterministic and local.
- Isolate `HOME`, data directory, debug log, config, and temporary files.
- Do not create tracked `testdata` directories; repository fixtures are generated in temporary directories or constants in `_test.go`.
- The self-hosting workspace begins clean at the exact source commit.
- The only intended source change is an exact replacement in `README.md` inside the disposable clone.
- Project trust is explicit through `/skills` under default `ask` policy.
- Child performs read, fixed-string search, exact edit, and focused shell verification.
- Parent inspects the child receipt and performs the complete verification command.
- Compaction records exact source range and summary evidence before restart.
- `--continue` must recover compaction, skill provenance, lineage, receipt, and workspace state.
- Existing journal bytes are prefix-preserved; uncertain effects are not retried.
- Supported release targets remain Darwin/Linux on amd64/arm64.
- Evidence reports never claim a command passed before it actually passes.
- Do not stage unrelated or pre-existing untracked files.
