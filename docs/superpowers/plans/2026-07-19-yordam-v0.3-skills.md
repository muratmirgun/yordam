# Yordam v0.3 Filesystem Skill System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Discover global and project `SKILL.md` files, bind them to immutable provenance and workspace trust, expose only metadata initially, and let the model load full instructions through a read-only catalog-bound `skill` tool.

**Architecture:** A new `internal/skills` package owns strict parsing, safe discovery, canonical identities, diagnostics, shadowing, catalog snapshots, and workspace trust projection. Project trust is a durable workspace-control decision over the canonical workspace plus catalog digest. The runtime generation freezes the active catalog and includes its revision in the manifest; system instructions expose only metadata, while a built-in `skill` tool accepts a canonical name from that catalog and returns exact content and provenance. Reload validates a complete candidate generation before activation.

**Tech Stack:** Go 1.26.4, strict JSONC, `io/fs` and UTF-8 validation, root-anchor/safe-file helpers, canonical JSON digests, event-envelope v2, application protocol v1, JSONL journals, Bubble Tea v2.

## Global Constraints

- Project path: `.yordam/skills/<name>/SKILL.md` below canonical workspace.
- Global path: `~/.config/yordam/skills/<name>/SKILL.md`.
- Names use lowercase ASCII letters, digits, and single hyphens; directory and frontmatter names match.
- Frontmatter has exactly `name` and `description`; reject duplicate or unknown keys.
- Each file is UTF-8, regular, non-symlink, and at most 128 KiB.
- Reject path traversal, symlinked roots/directories/files, binary content, duplicates, and identity ambiguity.
- A catalog contains at most 128 active skills.
- Global skills are active user-managed input.
- Project policy is `ask` by default; `allow` and `deny` are explicit alternatives.
- Under `ask`, project bytes are not model-visible until a durable decision matches canonical workspace and exact catalog digest.
- Project trust grants no file, shell, provider, child, or policy authority.
- Trusted project content shadows a same-name global skill; `/skills` shows both.
- System instructions receive metadata only. Full content loads only by name through the frozen catalog.
- The `skill` tool never accepts a path and is not a generic file reader.
- Reloaded files affect future runtime generations and turns only.
- Children inherit the exact frozen parent catalog and do not rediscover files.
- Skill instructions are untrusted context beneath system, user, and authorization policy.
- Do not stage unrelated or pre-existing untracked files.
