# Yordam v0.3 Native Context Compaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `/compact` a durable production operation and automatically compact before a known model context window is exhausted, without rewriting source journal history or silently retrying an uncertain provider request.

**Architecture:** A pure `internal/compaction` package selects a committed historical range, calculates trigger thresholds, and constructs a bounded provenance-bearing summary request. The orchestrator remains the only component allowed to authorize provider egress, persist summary evidence, and append `context_compacted_v1`; manual compaction acquires the existing compaction lane, while automatic compaction runs inside the already-owned turn lane before provider dispatch and then replans context. The context planner resolves native summary evidence through a read-only resolver and combines the latest valid summary with the uncompacted suffix.

**Tech Stack:** Go 1.26.4, event-envelope v2, application protocol v1, JSONL journal repository, evidence store, OpenAI-compatible provider service, Bubble Tea v2, strict JSONC configuration.

## Global Constraints

- The approved source is `docs/superpowers/specs/2026-07-19-yordam-v0.3-self-hosted-agent-runtime-design.md`, Sections 6 and 8.
- Never edit, delete, truncate, or replace source journal events or artifact blobs.
- Store summary evidence before appending `context_compacted_v1`; only the committed event activates the summary.
- Cap admitted summary content at `agent.MaxCompactionSummaryBytes`, currently 128 KiB.
- Manual compaction works with an unknown context window by selecting a conservative bounded input.
- Automatic compaction is unavailable when the selected model has no positive configured context window.
- Trigger automatic compaction when `estimated_input_tokens + output_reserve >= context_window - compact_reserve`.
- The default compact reserve is ten percent of the context window with a minimum of 2,048 tokens.
- Reject an explicit reserve/output/window combination that cannot fit.
- Cancellation, provider failure, evidence failure, or proven non-commit leaves the prior context active.
- An uncertain provider request is terminal and is never resent automatically.
- A provider `context_too_large` failure is reported with `/compact` guidance and is not silently retried.
- Existing valid legacy inline-summary compaction events remain readable.
- Preserve event envelope version 2 and application protocol version 1.
- Do not stage unrelated or pre-existing untracked files.
