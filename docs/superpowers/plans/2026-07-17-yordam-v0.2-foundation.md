# Yordam v0.2 Protocol Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Gate 1 of Yordam v0.2: versioned event and application protocols, committed journals, deterministic v0.1 upcasting, evidence and recovery-material stores, projections, catalogs, structured authorization, and a bounded turn orchestrator that preserves v0.1 behavior.

**Architecture:** Keep Yordam a modular Go monolith with one process, one active turn, and one serialized consequential-effect lane. Add v2 protocols beside the immutable v1 wire model, evolve the JSONL store into per-journal expected-head transactions, and make `internal/orchestrator.Service` the sole turn-journal committer and sole provider/effect dispatcher; bounded packages return plans, decisions, evidence candidates, or verification candidates but never append turn events. `internal/app` composes generations and exposes one versioned command/snapshot/event service, while a compatibility adapter preserves the current TUI until Gate 2 replaces its presentation.

**Tech Stack:** Go 1.26.4, standard `encoding/json`/`crypto/sha256`, `github.com/oklog/ulid/v2`, `golang.org/x/sys/unix`, the existing hardened `os.Root` JSONL storage, Bubble Tea v2, and deterministic local fakes.

- Literal provider API-key fields are absent from config decoding, schema, generated output, and persistence; credentials remain environment or credential-store references.
- Preserve one process, one active turn per application instance, sequential model tool intents, and one serialized consequential-effect lane.
- `restricted local` and `trusted local` are policy profiles, not operating-system sandboxes.
- Do not add final cockpit visuals, public checkpoint/rewind/restore commands, native provider network adapters, MCP/OAuth, project extensions, production headless CLI behavior, subagents, steering, or parallel effects.
- Journal envelope version is `2`; application protocol version is independently `1`; every known event payload starts at version `1`.
- Persisted identifiers are opaque strings; Go aliases improve type safety but never define wire compatibility.
- Existing v1 JSONL lines are never rewritten in place. The first v2 append to a legacy journal includes `migration.compatibility_declared` in the same committed transaction as the caller's first v2 events.
- Unknown event kinds and unsupported payload versions preserve their exact raw line but make the validated prefix read-only. Invalid known payloads are corruption. This follows the stricter Capability Contract rule.
- Transaction and manifest digests use SHA-256 over the canonical JSON profile defined in Task 1; checksums detect corruption and do not claim attacker-resistant authenticity.
- Digest-bearing records separate the canonical body from its digest: `ActionPlan`, `RuntimeGenerationManifest`, checkpoint, recovery-material, evidence-record, and receipt digests hash only their `*Body` value. The digest field is never included in its own input.
- Workspace-control journal ID is the canonical workspace ID. A session journal ID is its session ID.
- Runtime-generation identity is an opaque ID plus a mandatory canonical manifest digest.
- Existing configured-provider requests receive a durable compatibility-policy allow decision, preserving v0.1's lack of a provider modal while making egress authorization explicit.
- Until Gate 2 provides user-authored outcome contracts, current prompt submission creates a visible system-authored `v1_compatibility` contract with one required criterion, `legacy_turn_terminal`; the turn may complete, but the task outcome remains `unknown`, never `verified`.

## Fixed Design Decisions

1. Canonical JSON permits objects, arrays, strings, booleans, null, and base-10 integers. Object keys sort lexicographically by UTF-8 bytes; strings use `encoding/json` escaping; arrays retain order; floats, exponents, duplicate object keys, and trailing JSON values are rejected. A transaction digest hashes each canonical event envelope plus one `\n`, in sequence order.
2. Every physical v2 append writes one or more event envelopes followed by one `transaction.committed` envelope. The marker consumes the next local sequence but is excluded from domain projections.
3. A v1 line is an implicit one-event committed transaction with cursor transaction ID `legacy:<event_id>` and commit sequence equal to the v1 sequence.
4. A committed head is `{journal_kind,journal_id,commit_seq,transaction_id}`. Metadata and projection caches may lag and are rebuilt from the journal; they never lead the committed marker.
5. Incomplete v2 records are invisible. A later append returns `recovery_required` until explicit recovery quarantines the incomplete bytes. `commit_unknown` is resolved only through `LookupTransaction`; callers never retry blindly.
6. Per-journal `flock` protects append/recovery across processes on Darwin and Linux. In-process locks are keyed by journal, so unrelated sessions do not share one root-wide append lock.
7. A turn lease holds a second per-session `flock` for the complete turn. After obtaining the physical lock, acquisition checks the activity projection; a durable nonterminal turn returns `turn_recovery_required` instead of starting another turn.
8. Content blobs are workspace-scoped and content-addressed at `workspaces/<workspace-id>/evidence/blobs/sha256/<first-two>/<digest>`. Evidence records are separate immutable JSON metadata under `evidence/records/`.
9. Confidential recovery material is workspace-scoped under mode `0700`, with mode `0600` material files and metadata separate from ordinary evidence. Registered secret detection disables exact material before any temporary write.
10. Provider-visible built-in aliases remain `read`, `search`, `edit`, `shell` in that order. Authorization keys use canonical identity `builtin/yordam/<name>`, source revision, and descriptor digest.
11. The OpenAI-compatible adapter is the only production provider in Gate 1. It advertises text input/output, streaming, and tool use as supported adapter guarantees; all unsupported or unavailable normalized features remain `unsupported` or `unknown` and are never flattened silently.
12. Snapshot and subscription registration linearize under one projection lock. Durable catch-up reads strictly after each vector component and merges by event time then event ID. Transient events use process epoch plus sequence and emit `transient.gap` after an epoch change.
13. One application-scoped operation arbiter is acquired before a turn, control operation, recovery, compaction, or reload activation can enter the consequential lane. Lock order is operation lease, turn lease when applicable, then short-lived journal lock; code never waits for an outer lock while holding an inner lock. Pure candidate preparation acquires no operation lease.
14. Registered-secret admission is generation-aware and applies before journal, evidence, recovery, log, diagnostic, application-event, TUI/fake-headless, or model-visible result persistence/display. Retired generation registrations remain active until every producer and buffered stream from that generation closes.
15. Lock files are durable journal members opened through rooted regular-file operations, identity-verified before and after acquisition, and never renamed, removed, or replaced. Missing, symlinked, or substituted lock identity opens the journal read-only.

func TransactionDigest(events []protocol.EventEnvelope) (protocol.Digest, error) {
	hash := sha256.New()
	for _, event := range events {
		raw, err := Marshal(event)
		if err != nil { return protocol.Digest{}, err }
		_, _ = hash.Write(raw)
		_, _ = hash.Write([]byte{'\n'})
	}
	return protocol.Digest{Algorithm: "sha256", Value: hex.EncodeToString(hash.Sum(nil))}, nil
}
