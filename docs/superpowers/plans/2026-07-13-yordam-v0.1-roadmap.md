# Yordam v0.1 Implementation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved Yordam v0.1 as a tested, single-binary, open-source terminal agent for macOS and Linux.

**Architecture:** Build one Go process around a UI-independent agent runtime. Concrete model, tool, permission, storage, and TUI adapters connect through small internal ports; the in-memory app command/event bridge remains replaceable by IPC in a future daemon.

**Tech Stack:** Go 1.26.4, OpenAI-compatible Chat Completions over `net/http`, append-only JSONL, Bubble Tea v2, Bubbles v2, Lip Gloss v2, GitHub Actions, GoReleaser, Syft.

## Global Constraints

- Product, binary, and remote repository name: `yordam`.
- Go module path: `github.com/muratmirgun/yordam`.
- Supported operating systems: macOS and Linux only.
- Supported release architectures: `amd64` and `arm64`.
- License: Apache-2.0.
- Runtime shape: one process; one active turn per session; sequential tool execution.
- Provider surface: one OpenAI-compatible Chat Completions adapter with named endpoint/model profiles.
- Built-in tools: `read`, `search`, `edit`, and `shell` only.
- Default permission mode: `ask`; `safe` and `auto` must match the approved matrix.
- Built-in file paths must be canonicalized before authorization; no unapproved workspace escape.
- Shell execution is trusted and unsandboxed; automatic shell calls require the approved acknowledgement.
- Provider key variables must never be persisted and must be removed from shell child environments.
- Session storage is append-only JSONL plus artifacts; interrupted mutations are never replayed automatically.
- No telemetry, project-owned config, web/browser tools, Windows support, external plugin protocol, daemon, session branching, or parallel tool calls in v0.1.
- Use TDD for every behavior: failing focused test, observed failure, minimal implementation, focused pass, package/full pass, commit.
- Do not begin a later phase until the previous phase's completion gate passes.
