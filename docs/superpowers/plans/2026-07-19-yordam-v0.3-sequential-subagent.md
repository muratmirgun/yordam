# Yordam v0.3 Sequential Subagent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a parent turn delegate one bounded task at a time to one local depth-one child session, durably attach the exact terminal receipt, and resume the parent without concurrent workspace mutation or inherited permission grants.

**Architecture:** The provider sees a trusted built-in `subagent` descriptor, but the orchestrator intercepts that canonical tool identity before ordinary tool execution. It commits parent request/wait state, yields an owned global-lane lease, creates and runs one child through the normal orchestrator, then reacquires the parent lane and idempotently attaches the child receipt as the tool result. Child sessions have identity-only lineage, the same frozen runtime/model/skill catalog, a filtered tool exposure without `subagent`, a fresh session policy at the parent mode ceiling, and bounded tool/time budgets. A dedicated projector/reconciler handles terminal attachment and uncertain recovery.

**Tech Stack:** Go 1.26.4, event-envelope v2, application protocol v1, JSONL session store, existing orchestrator/provider/tooling/authorization/evidence/recovery layers, Bubble Tea v2.

## Global Constraints

- Exactly one active child per parent and no parallel execution.
- Delegation depth is one; a child never sees or invokes `subagent`.
- The parent and child never own the mutation lane concurrently.
- Parent commits request and waiting state before child session creation or provider egress.
- Child terminal receipt commits before parent attachment.
- No cross-journal atomicity is claimed.
- Default maximum attempts per parent turn is 4.
- Default child tool-call limit is 16; valid range is 1..64.
- Default child wall time is 600 seconds; valid range is 1..1800.
- Child uses the parent selected provider/model and exact frozen skill catalog.
- Child inherits parent mode as a ceiling, hard-denies, workspace, provider catalog, and tool catalog.
- Child does not inherit allow-once decisions, session grants, trusted-shell acknowledgement, or pending approvals.
- Child tool/provider actions use ordinary authorization and durable activity ordering.
- Retry is explicit and creates new attempt and child session identities.
- Terminal states are `succeeded`, `failed`, `cancelled`, and `uncertain`.
- Unknown mutation effects are never automatically repeated.
- `Esc` cancels child work and the waiting parent operation.
- Existing non-subagent turns and checkpoint lineage remain byte-compatible/readable.
- Do not stage unrelated or pre-existing untracked files.
